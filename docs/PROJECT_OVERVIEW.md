## 1. 这是什么

My Quant Lab（MQL）是一套**自托管的个人量化策略研究实验室**：跑在你自己的 NAS 上，用浏览器访问，
数据存在你自己的数据库里，不依赖任何云服务、也不需要券商账户。

它把「我有个想法」到「一份可回测、可复现、能说清风险的研究结果」这条链子做成一个有记录的流水线：
研究材料 → AI 理解 → 策略假设 → 策略草案 → 人工确认 → 编译成不可变策略版本 → 回测 →
收益/风险/对照分析 → 实验比较 → 模拟验证。

技术栈：Python 3.12 + FastAPI + PostgreSQL 16 + Redis 7 + Celery + Vue 3，用 Docker Compose 部署，
MIT 许可。界面是简体中文，有「普通模式 / 高级模式」两种显示方式（同一套计算，只是显示多少）。

## 2. 它解决什么问题

- **把想法变成可验证的东西**：一句话的想法，经由 AI 理解与结构化草案，变成一份声明式策略（Strategy DSL），
  再由**确定性**的编译器与回测引擎处理；AI 不参与任何数值计算。
- **让结果可复查**：每次回测都留下结果哈希（策略版本 + 数据集哈希 + 参数 + 引擎版本 + 特征版本），
  同样的输入必须得到同样的结果；策略版本不可变、可校验。
- **让风险看得见**：每次结论都同时给出最大回撤、最长连续亏损、样本量是否足够、以及「跟一直拿着比怎么样」。
  算不出来的读数写「未知」，**绝不写成 0**。
- **不碰真钱**：系统里不存在任何券商下单端点；模拟账户用虚拟资金，与真实持仓（Ghostfolio，只读）完全隔离。

## 3. 适合什么人使用

- 想认真研究美股 / ETF / 加密货币策略、但不想把数据和研究过程交给第三方的个人研究者。
- 有 NAS（飞牛 fnOS / 群晖等）与 Docker 图形界面、愿意自己维护一套自托管服务的用户。
- 能接受「研究工具」而不是「赚钱机器」的定位：结论需要自己判断，系统只负责把事实摆清楚。

## 4. 它明确不做什么（五条不可逾越的红线）

| # | 红线 | 实现方式 |
|---|------|----------|
| 1 | **不自动交易** | 代码中不存在任何券商下单端点，测试 `test_no_broker_endpoint_exists` 强制校验 |
| 2 | **AI 不决定量化结果** | 所有指标由 `backend/app/research/metrics.py` 计算；AI 只做解释（`backend/app/ai/`） |
| 3 | **回测必须可复现** | 结果哈希 = 策略版本 + 数据集哈希 + 参数 + 引擎版本 + 特征版本 |
| 4 | **真实持仓与模拟盘隔离** | Ghostfolio 只读；模拟账户使用独立表与虚拟资金 |
| 5 | **GitHub 代码视为不可信输入** | 导入器只做文本/结构分析，不执行第三方代码 |

这五条不是口号：每一条都有对应的测试或代码结构，改动它们会被 CI 拦住。

## 6. 你能完成的主要任务（端到端）

| 想做的事 | 在哪个页面做 | 结果落在哪里 |
|---|---|---|
| 同步行情、看数据质量 | 「数据」`/data` | 数据库里的行情系列（K 线） |
| 从一句想法开始研究 | 「AI 研究实验室」`/lab` ① 研究输入（贴文字 / 给网址 / 传 PDF） | 一条研究运行 + 材料快照 |
| 让 AI 理解并给出假设与草案 | `/lab`（AI 异步跑，可轮询） | 策略假设 + 策略草案（带能力检查） |
| 回答编译器问的问题 | `/lab` 卡⑥ 的作答表单 | **新的一版草案**（旧的那一版原样保留） |
| 人工确认草案 | `/lab`（确认 / 需修改 / 拒绝） | 确认记录；未确认不能编译 |
| 编译成策略版本并激活 | `/lab` 卡⑥ / 「我的策略」 | 不可变的策略版本（可校验哈希） |
| 跑一次历史回测 | 「研究策略」`/research` 四步，或「回测」`/backtest` | 一次回测记录（结果哈希 + 指标 + 交易明细） |
| 看结论、风险与对照 | `/backtest` 结果区（结论卡 → 可信程度 → AI 汇总 → 绩效/风险/对照 → 曲线） | 只读展示，不重算 |
| 比较两次研究、管理实验 | 「实验」`/experiments` | 实验记录（配置冻结 + 结果） |
| 看研究信号、去模拟验证 | 「信号」`/signals` → 「模拟验证」`/paper` | 模拟订单、持仓、资金流水 |

## 7. 系统的主要组成部分

**运行时：三个容器、四个进程**（`docker-compose.yml`，`name: my-quant-lab`）

| 容器 | 里面是什么 | 对外 |
|---|---|---|
| `quantlab-app` | nginx（Web 与 API 反向代理）+ uvicorn（FastAPI）+ Celery worker + Celery beat | 发布 `${WEB_PORT:-8081}`（你唯一需要访问的端口）与 `${API_BIND:-127.0.0.1}:${API_PORT:-8080}`（诊断用） |
| `quantlab-postgres` | PostgreSQL 16 | 只在内部网络，不对外暴露 |
| `quantlab-redis` | Redis 7（Celery 消息与结果） | 只在内部网络，不对外暴露 |

数据卷三个：`postgres_data`、`redis_data`、`celery_beat`。
**只允许运行一个 `quantlab-app` 实例**：它是唯一持有定时调度（beat）的容器，第二个实例会让定时任务重复触发。
容器启动时会自动执行数据库迁移（`alembic upgrade head`），迁移失败会直接启动失败并打印原因。

**后端主要模块**（`backend/app/`）

| 目录 | 负责 |
|---|---|
| `api/` | FastAPI 应用、路由、请求/响应 schema、中间件（鉴权与限流） |
| `core/` | 配置（环境变量）、日志、时区与通用基础设施入口 |
| `domain/` | SQLAlchemy 模型（数据库表的唯一定义处）与出站协议定义 |
| `data/` | 行情仓库与数据质量、回测服务、策略服务、审计、Ghostfolio 只读适配器（`data/ghostfolio.py`） |
| `features/` | 技术指标与价格行为特征（确定性计算，回测与信号共用） |
| `research/` | 确定性回测引擎与指标计算（所有数字的来源） |
| `simulation/` | 信号引擎、结果回填、模拟账户与模拟成交 |
| `strategies/` | Strategy DSL、校验器、生命周期、执行器 |
| `compiler/` | 策略编译器（草案 → 策略规格，纯函数、无 AI、无数据库写入） |
| `ai/` | AI 层：角色契约、Provider 调用、研究流程、草案 schema、人工确认、解释 |
| `notifications/` | 信号通知渠道（Webhook / 飞书 / Telegram / PushPlus / 邮件）、去重、静默时段与每日上限、投递记录 |
| `sources/` | 外部材料抓取（网址 / PDF / 文本）与 SSRF 守卫 |
| `importer/` | GitHub 仓库静态分析（只读，绝不执行代码） |
| `infrastructure/` | 限流等跨模块支撑 |
| `workers/` | Celery 应用与任务（定时同步行情、扫描信号、发通知、跑回测与 AI 研究） |
| `capabilities.py` | 能力注册表：系统支持哪些指标/算子/风控/执行/分析引擎，不支持时给什么理由 |

**前端**（`frontend/src/`）：10 条导航页面（研究首页 `/`、研究策略 `/research`、我的策略 `/strategies`、
回测 `/backtest`、实验 `/experiments`、模拟验证 `/paper`、信号 `/signals`、数据 `/data`、
AI 研究实验室 `/lab`、系统管理 `/settings`），外加不占导航的策略详情页 `/strategy/:strategyId`
与一个「路走错了」的兜底页。

## 8. 数据如何进来、AI 怎么参与、策略怎么被确认和回测

1. **数据进来有两条路**：定时任务（Celery beat）按 `MARKET_DATA_WATCHLIST` 自动同步行情；
   你在「数据」页手动同步某个代码。研究材料则从 `/lab` 进来（贴一段文字 / 给一个网址 / 传一份 PDF），
   服务端会把材料存成快照，研究时按快照读回当时保留的那一份。
   抓取外部网址要过 SSRF 守卫（协议、端口、重定向、DNS 都校验），机器人协议不允许就直说读不到。
2. **AI 只做理解与解释**：它把研究问题与材料变成结构化的策略假设与草案，或者把已经算好的数字翻成人话。
   它不产生任何指标、不写任何策略版本、不执行任何交易；草案必须通过研究层门禁（schema、
   证据、能力评估），再经**人工确认**才能编译；未确认的草案编译会被服务端直接拒绝。
3. **策略是声明式的、不可变的**：编译器把草案变成一份策略规格（Strategy DSL）；
   编译成功产生一个不可变的**策略版本**，可校验哈希。策略自己不点名标的：
   标的在回测请求里由你选（这是有意为之，见 [当前开发计划](./DEVELOPMENT_PLAN.md) 的待决事项）。
4. **回测是确定性的**：同一份策略版本、同一份数据、同一套参数，必须得到同样的结果哈希。
   回测可以在后台跑（能看到进度与当前步骤），失败了会逐字给出服务端原因并允许原地重试。
5. **每一步都留记录**：研究运行、草案、确认、编译、策略版本、回测、实验、模拟成交都落库，
   关键动作写审计日志；模拟执行同一个信号只会产生一笔订单（重复请求幂等返回第一次那笔）。

## 9. 已知限制与尚未完整验证的功能（摘要，详见开发计划）

- **策略不能自己点名标的**：草案里写了 `universe` / `markets` 会被编译器判为「不可表达」，
  这类草案停留在需要人处理的状态，**目前没有自动修复通道**——它需要先决定改哪一侧的契约（待你决定）。
- **不支持做空**：草案要求做空（`market.allow_short`）时编译器会说需要人决定，
  但目前的草案格式没有承载这个答案的字段，因此这类策略**暂时无法编译**（待你决定）。
- **模拟执行幂等的生产存量未验证**：代码与迁移都会自动检查并拒绝「同一个信号已有多笔订单」的升级，
  但你的生产库里**是否已经存在**这种历史重复，只有你那边能看（本机无法访问生产库）。
- **数据质量不拦截下游**：数据被标成「有空洞 / 有问题」只会在界面上警告，回测与信号不会因此被挡住。
- **回测结果哈希的口径偏窄**：它包含策略版本名、数据集哈希、引擎/特征版本、参数与指标，
  但**不含策略 DSL 正文**；扩大口径需要同时提升引擎版本号，属于要慎重的一次性变更。
- **前端没有自动化测试框架**：前端的关键约定目前靠 Python 侧的文本扫描守卫兜住。
- **默认没有登录**：界面本身没有账号体系；部署默认对局域网开放（有写请求限流），
  可用 `API_AUTH_TOKEN` 与 `WEB_BIND` 收紧，见 [开发指南](./DEVELOPMENT_GUIDE.md) 的安全边界一节。
- **AI 线路没有自动重试与故障转移**：外部 AI 服务抖动时不会自动换线路重试，只如实报错
  （重试可能重复计费，所以这是一个需要你决定的产品取舍）。通知渠道支持 Webhook / 飞书 /
  Telegram / PushPlus / 邮件，投递失败会记成事件，重复扫描不会重复发送。
